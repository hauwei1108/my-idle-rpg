# 一份 JSON 的 Google 帳號雲端存檔

## 完成的功能

每個 Supabase Auth User ID 對應 public.game_saves 的**一筆 JSONB 紀錄**，並設定 RLS。原本遊戲用 localStorage 與 \`_lzGet\`、\`_lzSet\`、\`_saveWrap\` 讀寫進度的方式不變；雲端只負責讀取或還原既有存檔內容。

**涵蓋資料：** 8 個角色欄位、一般/經典共用倉庫與領出墓碑、寵物與放生墓碑、卡片/裝備/道具/遺物圖鑑、血盟、龍之鑽石與潘朵拉共用狀態、傭兵雇用索引與經驗帳本、全域自動販賣設定。保存為 \`{ format: "idle-rpg-cloud-bundle", schema: 1, entries: { 存檔鍵: 原本遊戲儲存的內容 } }\`。

**刻意排除：** Supabase 認證令牌、其他網站的 localStorage、遊戲分頁活躍鎖、同步標記、快取、舊版備份桶。僅同步明確列出的遊戲資料。桌面安裝版不開啟此網頁雲端存檔功能。

## 玩家操作

1. 首先用 Google 一鍵登入。
2. **第一次使用**：如果雲端還沒有進度，在標題畫面右上角選擇「上傳本機存檔」。如果雲端已有進度，可選擇「下載雲端存檔」。
3. 上傳成功後，每 60 秒嘗試將目前進度同步。同步前會先讓遊戲把當前角色存回本機。
4. 另一台電腦同帳號登入後，選擇「下載雲端存檔」再重新載入遊戲。
5. 下載雲端資料會**取代本機**的八個角色欄位與部分共用資料。玩家會先看到確認視窗，程式會自動下載一份本機 JSON 備份；遊戲中或有其他分頁執行時禁止還原。
6. 登出時停用雲端同步，本機存檔仍保留。不同 Google 帳號登入時不會自動上傳，必須重新明確確認綁定。

## 版本衝突

雲端紀錄有 \`revision\` 整數。寫入時使用 \`UPDATE ... WHERE user_id = ... AND revision = ...\` 的條件更新；若另一台裝置已先寫入，舊版本不能自動覆蓋，會顯示「自動同步已暫停」。玩家要從標題畫面自行選擇上傳本機（覆蓋雲端）或還原雲端（覆蓋本機）。

這是避免意外覆蓋的**基本保護**，不是遊戲交易的一致性保障，也不是反作弊服務。不能用於需要伺服器保證的 PvP、多人市場或價值轉移。

- **保護重要存檔：** 使用前先額外透過「匯出進度」備份。網頁自動下載的還原備份包含八格與共享資料，不等同既有的單角色匯出檔，不能直接套用單格匯入按鈕；可供技術人員協助恢復。
- 網頁用 \`SIG1\` 格式校驗存檔完整性（非可信伺服器防作弊簽章），資料庫身分與擁有權由 Supabase Auth + RLS 控制。
